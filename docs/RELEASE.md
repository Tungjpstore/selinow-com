## Deployment command safety

`npm run deploy` intentionally fails with `deploy_environment_required`; the deploy entrypoint never infers a remote target. Use `npm run deploy:dry-run` for local packaging, `npm run deploy:staging:dry-run` for staging packaging, and `npm run deploy:staging` only during an approved staging change. Keep operator roles separate: `CLOUDFLARE_PLATFORM_API_TOKEN` admits staging platform/SaaS state, `CLOUDFLARE_ROUTE_AUDIT_API_TOKEN` reads route/domain inventory, `CLOUDFLARE_STAGING_RESOURCE_AUDIT_API_TOKEN` reads staging KV/R2/Queue/Worker-secret inventory, `CLOUDFLARE_PRODUCTION_PROMOTION_AUDIT_API_TOKEN` reads production Worker deployment/version inventory, `CLOUDFLARE_D1_API_TOKEN` is the short-lived least-privilege D1 token for backup/restore/migration (mapped to `CLOUDFLARE_API_TOKEN` only inside the child Wrangler process), and `CLOUDFLARE_WORKER_DEPLOY_API_TOKEN` is the dedicated Workers Scripts token for the final Worker deploy sink. When the staging resource-audit token is absent, doctor retains a compatibility fallback to the D1 token; new ceremonies should use the separate read-only role. The runtime Worker secret `CLOUDFLARE_API_TOKEN` is never operator input. Every staging mutation path—`backup:create`, `db:migrate`, `db:seed` and `deploy:staging`—requires the appropriate temporary tokens, a full `platform:doctor` pass, exact generated-manifest account/D1 name+UUID identity, the live D1 name+UUID admission and an immediate `whoami` plus route-audit repeat. Real staging deploys also require fresh report-v2 backup evidence for the exact admitted account/D1 target after the build and before the final admission/sink. Operator tokens are stripped from backup/restore child processes and never enter application build. A non-dry-run `--env local` invocation also fails with `remote_deploy_target_required` because Wrangler's base configuration would still deploy a remote Worker.

For an existing staging change, use this guarded order:

```bash

npm run backup:create -- --env staging --json

npm run release:staging:manifest -- --write --json
# Use the exact manifestRef emitted by the previous command.
MANIFEST_REF=".wrangler/releases/staging/<release-id>/release-manifest.json"
npm run db:migrate -- --env staging --confirm-maintenance-drain --release-manifest "$MANIFEST_REF"
```
