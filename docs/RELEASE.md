## Deployment command safety

`npm run deploy` intentionally fails with `deploy_environment_required`; the deploy entrypoint never infers a remote target. Use `npm run deploy:dry-run` for local packaging, `npm run deploy:staging:dry-run` for staging packaging, and `npm run deploy:staging` only during an approved staging change. Every staging mutation path—`backup:create`, `db:migrate`, `db:seed` and `deploy:staging`—now requires both temporary operator tokens, a full `platform:doctor` pass, exact generated-manifest account/D1 name+UUID identity, the live D1 name+UUID admission and an immediate `whoami` plus route-audit repeat. The route audit requires `selinow.com/*` and `*.selinow.com/*` to be `script=null`, `*.staging.selinow.com/*` and `*/*` to point to `selinow-com-staging`; malformed, duplicate or extra script/null-script routes fail closed. Real staging deploys also require fresh report-v2 backup evidence for the exact admitted account/D1 target after the build and before the final admission/sink. Operator tokens are stripped from backup/restore child processes and never enter application build. A non-dry-run `--env local` invocation also fails with `remote_deploy_target_required` because Wrangler's base configuration would still deploy a remote Worker.

For an existing staging change, use this guarded order:

```bash
npm run deploy:staging:dry-run
npm run platform:route-preflight -- --json
npm run platform:doctor -- --env staging --json
npm run db:migrate:status -- --env staging
npm run db:preflight -- --env staging --json
npm run backup:create -- --env staging --dry-run --json
npm run backup:create -- --env staging --json
npm run db:migrate -- --env staging
npm run db:migrate:status -- --env staging
npm run db:preflight -- --env staging --json
# Run only when the reviewed change explicitly requires a seed.
npm run db:seed -- --env staging
npm run platform:doctor -- --env staging --json
npm run deploy:staging
npm run db:migrate:status -- --env staging
npm run db:preflight -- --env staging --json
npm run platform:route-preflight -- --json
npm run platform:doctor -- --env staging --json
# Run the bounded public staging browser gate only after the deploy is admitted.
npm run test:visual:staging
```

The dedicated route preflight is staging-only and read-only: it requires only the temporary route-audit token, verifies the checked-in account/zone/Worker/D1 target, pins Wrangler account context, and performs one Worker Routes `GET`. It emits safe check metadata without the token, raw API response or route IDs. It is an early evidence checkpoint, not mutation admission. The first doctor call must still have both temporary operator tokens and admit the full platform plus live route inventory before the protected backup and any migration.
